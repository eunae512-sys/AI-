## 1. 백엔드 — image-to-image 편집 지원

### 1a. types.ts
- ImageGenInput 에 `inputImage?: string;` 추가 (data URL "data:image/...;base64,..." 또는 https URL). 주석: 있으면 image-to-image 편집.

### 1b. gemini.ts (Nano Banana 편집)
- nanobanana 분기에서 input.inputImage 가 있으면 contents 를 배열로:
  `contents: [{ inlineData: { mimeType, data } }, { text: input.prompt }]`
  - data URL 이면 정규식으로 mimeType+base64 추출.
  - https URL 이면 fetch→arrayBuffer→base64, mimeType 은 응답 content-type(기본 image/jpeg).
- inputImage 없으면 기존 text-only 동작 그대로(회귀 없음).
- imagen 분기는 편집 미지원 — inputImage 와 무관하게 기존 동작(편집은 index 가 nanobanana 로만 보냄).

### 1c. index.ts
- 편집 전용 프로바이더 접근자 추가: `export function getEditProvider(): ImageProvider { return new GeminiImageProvider("nanobanana"); }` (편집은 Nano Banana만 가능). 기존 selectImageProviderChain 무변경.

### 1d. app/api/generate-poster/route.ts (신규)
- runtime nodejs. body: { inputImage(필수, data URL), prompt(필수, 템플릿 결과), size?="1024x1536", styleId?, slideId? }.
- 검증: inputImage·prompt 없으면 400.
- 게이팅: ensurePlanAndQuota({feature:"ai-image:generate", usage:{kind:"aiImage"}}) — generate-image 와 동일. unauthorized 면 비로그인 데모 통과(userId=null), limit_exceeded/feature_locked 면 ok:false + 친절 메시지(편집은 Pexels 폴백 불가라 데모 이미지로 대체하지 말 것 — 원본을 가짜 포스터로 둔갑시키면 정직성 위반).
- 키 미설정(GOOGLE_GENAI_API_KEY 없음): ok:false, error "AI 포스터 편집은 Google 이미지 키가 필요합니다" (UI 토스트). 원본을 포스터라고 반환 금지.
- 프로바이더: getEditProvider().generate({ prompt(템플릿 그대로 — no-text 강화 금지), size, quality:"medium", inputImage, signal }).
- 성공: 로그인+data URL 이면 persistImage(image,userId), bumpUsage(userId,"aiImage"). 반환 { ok:true, image, meta:{ source:"gemini-nanobanana-edit", model, latencyMs, costKrw, styleId } }.
- 실패(ProviderError): ok:false + status/메시지.

  - local(패션): 룩북 플랫레이 + 디테일(원단·실루엣) 콜아웃, 미니멀 프로덕트 카드.
